# Luma Browser Screen Structure

**Date:** 2026-11-25  
**Applies to:** `luma-companion-2` 0.1.0 (`com.luma.companion2`)  
**Status:** implemented and statically verified. Physical TV rendering has not been captured.

## 1. Purpose

This document maps the browser shell in `luma-companion-2/index.html` to the modules that own
each region. It is the reference for adding a screen or a control without duplicating state or
reintroducing the old single-frame browser card.

The browser keeps the Phase 1/2 dashboard as a **Companion** screen instead of replacing it.

## 2. Top-level shell

```text
#browser-app                     .browser-shell .app-shell
├── #browser-topbar              tab bar, new tab, overflow, Settings
├── #browser-navbar              navigation buttons, address/search, utilities
├── .browser-workspace
│   ├── #browser-sidebar         collapsible side menu
│   └── .browser-main
│       ├── #browser-frames      one sandboxed iframe per open tab
│       ├── #browser-screen      home / bookmarks / history / tabs / settings / video
│       ├── #suggestion-layer    address suggestions
│       ├── #browser-overlay     loading, error and Stop/Retry controls
│       └── #companion-screen    preserved Phase 1/2 dashboard
└── .browser-statusbar           page, tab count, session, network
```

Only one main surface is visible at a time:

- **Page screen:** `#browser-frames` is visible, `#browser-screen` is empty, `#browser-overlay`
  shows loading/error when needed.
- **Browser screens:** `#browser-frames` is hidden, `#browser-screen` renders Home, Bookmarks,
  History, Tab Manager, Settings or Video.
- **Companion screen:** both `#browser-frames` and `#browser-screen` are hidden,
  `#companion-screen` is visible.

The status bar is always visible and informational; it has no fake action.

These IDs are generated by `browser-components.js` and therefore are not present in the
static HTML source. DOM metadata checks treat them as known generated IDs.

| ID or pattern | Region |
|---|---|

| `home-search-input` | Home search field |
| `bookmark-search-input` | Bookmark manager filter |
| `history-search-input` | History filter |
| `bm-title-<id>`, `bm-url-<id>` | Bookmark edit fields |
| `setting-homepage`, `setting-engine`, `setting-startup`, `setting-zoom`, `setting-accent`, `setting-sidebar`, `setting-autoplay`, `setting-volume` | Settings controls |

## 5. Script order and dependency rule

```text
css/styles.css  →  css/browser.css
js/remote-contract.js
js/storage.js
js/diagnostics.js
js/remote-session.js
js/browser-view.js
js/browser-model.js
js/browser-components.js
js/browser-controller.js
js/app.js
```

`browser-view.js` must load before the model because the model uses `validateUrl()`.
The model must load before components and controller because they render its snapshot.
`app.js` loads last and calls `LumaBrowserController.init()` before its own lifecycle
`activate()`. This wiring is asserted by `dom-meta-check.js`.

`app.js` does **not** call removed APIs such as `LumaBrowserView.snapshot()`,
`subscribe()` or `init()`. Browser work is delegated to
`LumaBrowserController.command()`.

## 6. Render pipeline

1. `LumaBrowserModel` owns state and emits a snapshot on every mutation.
2. `LumaBrowserController` subscribes once and calls `render(snapshot)`.
3. `render()`:
   - updates `window.LumaDiagnosticsInfo.viewport` and `.dpr`,
   - applies the selected accent CSS variables,
   - re-renders top bar, navigation bar and side menu,
   - calls `view.syncTabs(snapshot.tabs)` to destroy frames for closed tabs,
   - calls `renderScreen(snapshot)`,
   - consumes a one-shot `loadRequest` by calling `view.load()`,
   - arms the 18 second load watchdog when a navigation starts,
   - applies zoom to every live frame,
   - updates status text and restores focus.
4. `view.onLoad()` clears the watchdog and calls `model.markLoaded()`.
5. `view.onError()` clears the watchdog, requests focus on the overlay, marks the error and
   renders again.

Typing in a filter input re-renders only the affected screen and restores focus by key; it does
not re-render the top bar or navigation bar.

## 7. Screen behaviour

| Screen | Source | Main behaviour |
|---|---|---|
| `home` | `ui.home()` | Search, Quick Access, Frequently visited, Recently opened, Bookmarks, Recent tabs, detected engine/viewport. |
| `page` | `#browser-frames` | Live sandboxed website frame; overlay for loading/error; no page-content reads. |
| `bookmarks` | `ui.bookmarks()` | Search, open, edit and remove local bookmarks. |
| `history` | `ui.history()` | Grouped local history, filtering, remove and clear. Query values are stripped from display. |
| `tabs` | `ui.tabManager()` | Cards with title, saved address and honest loading state; no live previews. |
| `settings` | `ui.settings()` | Only implemented controls, plus honest notes for cookies, permissions, subtitles and DRM. |
| `video` | `ui.video()` | Direct video file player, or an explicit unsupported state. |
| `companion` | existing HTML | LAN form, platform info and diagnostics from Phase 1/2. |

Default startup is Home / New Tab. If Settings chooses Homepage, `model.init()` navigates to the
saved homepage. If it chooses Restore and saved tabs exist, saved tabs are loaded and the active
tab returns to the page screen.

## 8. Frame lifecycle

- At most 8 tabs; each tab has its own iframe.
- `view.load(tabId, url, zoom)` creates or reuses a frame, sets `sandbox="allow-scripts
  allow-forms"`, applies `style.zoom`, sets `src` and shows only that frame.
- `view.showFrame(tabId)` displays one frame and hides the rest.
- `view.setZoom()` updates a frame without reloading it.
- `view.reload()` reassigns the same `src`.
- `view.stop()` tries `contentWindow.stop()`; on a cross-origin frame it blanks the frame
  instead. No framed document is inspected.
- `view.syncTabs()` destroys frames whose tabs no longer exist.
- `view.close()` clears the frame host and returns the model to Home.
- On app hide, `app.js` calls `LumaBrowserController.suspend()`; frames are hidden and the video
  is paused. The LAN socket is suspended separately by `LumaRemoteSession.suspend()`.

## 9. State and persistence

`browser-model.js` persists under `localStorage` key `luma.browser.v1`:

- settings: homepage, search engine, startup, accent, zoom, sidebar-at-startup, direct-video
  autoplay and volume,
- bookmarks and Home shortcuts,
- local history entries,
- saved tabs for Restore startup.

Per-tab back/forward stacks and the current `loadRequest` are in-memory. History stores URLs
that the user opened locally; it is never sent as telemetry. The status bar and overlays use
`model.sanitizeUrl()` so query parameters are not shown as primary text.

## 10. Boundary notes

- Iframe sandbox deliberately excludes `allow-same-origin`, `allow-top-navigation`,
  `allow-popups` and `allow-downloads`.
- Third-party sites may block framing through X-Frame-Options or CSP. The app reports the frame
  result honestly and never promises a site works.
- No system-browser Luna launch, DRM player, HLS/DASH pipeline, cookie editor, download
  manager or native-4K claim exists.
- The Developer Mode passphrase is not written to this project, its docs, logs or commits.
